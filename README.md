# これで誰でも雑談マスター — AI HACK × Even G2

「これで誰でも雑談マスター」は、懇親会や打ち合わせで出た人名・会社名をEven G2で捉え、AIが公開サイトや利用可能なSNSを調べ、出典付きの短い話題カードを表示するサービスです。約2人でCodex・AWS AI-DLCを使います。

**現在の状態：MVPを実装しました。ブラウザーの架空データによる調査、根拠表示、同姓同名の確認、障害時の縮退を利用できます。OrcaRouter・Tavily・Xを使う出典付き調査と、PCから公開英語サンプル音声を使ったストリーミング認識を確認しました。日本語会話・Even G2の実機動作は未検証です。提出完了ではありません。**

ユーザーが提示済み要件を確認し、通常のレビュー・テスト・マージをCodexへ委任しました。[決定記録](docs/DECISIONS.md)。約2人で開発する想定で、2人目のGitHub招待はユーザー名待ちです。

## 起動と確認

Node.js 24を推奨（22.18以上）。

```sh
npm ci
npm run dev
```

[ローカル画面](http://localhost:4173)で「架空の会話を入力」→「調査を始める」。通常／同姓同名／検索障害／根拠なしを切り替えられます。デモは架空の固定資料のみ使い、外部APIへの通信や課金は行いません。

```sh
npm run check
npm run test:coverage
npm run build
npm start
```

`npm start`はビルド済み画面とAPIを同じサーバーで配信します。[実行・設定ガイド](docs/RUNNING.md)に認証、費用上限、音声、G2接続、復旧方法を記載しています。[実装・検証記録](docs/validation/MVP_IMPLEMENTATION.md)に仕様とテストの対応、独立レビュー、未達を記録します。[実API検証記録](docs/validation/LIVE_API_VALIDATION.md)にライブ実行と費用の実測を記載しています。追加の[Xプロフィール入力検証](docs/validation/X_PROFILE_INPUT.md)も参照してください。

## エージェントがすること

入力から対象を計画 → 公開検索 → 本文取得 → 人物と根拠を検証 → 必要なら追加調査 → 最大4件の事実と質問を同時表示。スマホは2×2、G2は4組を表示し、質問に「⭐️推奨質問：」を付けます。事実は28字以内・質問は26字以内の短い表示文を優先し、省略記号で切らず、安全に短縮できない場合は元の全文を使います。G2の質問・出典本文は14pxの小さい文字で描画します。全文が収まらない場合や画像非対応時は標準文字へ戻し、人物一覧と音声状態は標準文字を維持します。原文と出典はスマホで確認できます。足りない枠は「未確認」とし、4件に埋めるための推測はしません。曖昧な人物は利用者へ確認し、本文やAPIの障害時は検証済みの情報へ縮退します。

Xを使える場合は「最近X」2件・「過去X」1件・「人物・会社」1件を優先します。「最近X」はそのアカウントの最新投稿で、直近7日間を意味しません。「過去X」は全期間の検索で取得した最大20候補の中から反響を比べて選び、歴代最多とは表示しません。スマホで投稿日と取得時の反響数を確認できます。特定の種類が不足した場合は別の検証済み話題で補い、実際の種類を表示します。根拠不足なら4件未満で終了します。[選定範囲・設定](docs/RUNNING.md#xの4枠構成と選定範囲)。

- **入力・表示**：手入力、同意後の最大30秒の短い録音、または明示開始する継続会話モード。スマートフォンの出典詳細とEven Hub SDK経由のG2表示。
- **会話モード**：音声を届いた順にOpenAI `gpt-live-transcribe`へサーバー経由で送り、途中の文字を即時表示。約5秒ごとに確定した発話からOrcaRouterが人物名と判明した会社名を抽出し、公開調査と質問生成を行います。公開人物は会社名なしでも調べられます。調査中も音声認識は別接続で継続し、調査待ちは最新の確定発話だけを保持します。同じ対象は120秒、結果なしは30秒の再検索を抑制。会話中は認証の無操作15分期限を更新し、開始から最大12時間と設定済み予算を上限とします。人物抽出の要求履歴は最新100件まで保持し、非表示・切断・終了後は自動再開しません。
- **制限**：最初の調査は20秒、速報後の追加調査を含む全体は90秒、個別操作8秒（Xの4枠構成の根拠評価のみ最大12秒、人物抽出＋必要時の補正は計16秒）、初期段階はLLM3回・検索2回まで、追加調査を含む全体はLLM6回・検索/API5回まで。Xの4枠構成・追加SNSでは根拠資料6件以内、それ以外は4件以内。会話の音声認識と人物抽出にも別途同じ会話予算を適用します。実APIは鍵と予算が揃うまで停止。
- **保護**：サーバー側の鍵管理、利用コードと短期認証、URL/DNS/転送先の検査、暗号化セッションと、認証延長で引き延ばさない最大15分の会話データ保持。終了後も匿名の費用予約は維持。
- **費用**：呼出前に最大見積額を留保。料金不明を0として扱いません。API側の明細との照合は未実施です。

会話モードは、サーバーだけに`OPENAI_API_KEY`と`STREAMING_ASR_MAX_USD_PER_MINUTE`を設定したうえで、会話相手への説明・同意を利用前に済ませて、「実APIで調査」→「会話モードを開始」で使います。毎回の同意チェックボックスは使いません。専用の会話用QRを読み取った場合は、その操作を開始要求としてQRの有効性を確認し、G2・ASR準備後に一度だけ開始します。通常ページや履歴復帰だけでは開始しません。[QR開始の仕様・確認状況](docs/specs/09_QR_CONVERSATION_START.md)。アプリが第三者の同意を取得したという証跡は作りません。「会話モードを終了」または「中止」で停止し、「終了して削除」で会話と端末の認証記憶を削除・失効させます。会社名がなくても公開人物を一般Web検索で調べ、本人への帰属を根拠で確認します。ひらがな・カタカナの表記差を扱い、公開一次資料で確認した「ひろゆき」→`@hirox246`、「ホリエモン」→`@takapon_jp`と、「ちょまど」→`@chomado`を会社名なしでも利用できます。事前登録がない人物もWeb調査の対象ですが、任意の別名からXアカウントを特定する保証はありません。公開一次資料に基づく15人の氏名・公開名・読みを拡張可能なカタログで管理します。「広行」のような音声認識の誤記は訂正候補として分離し、確認済み別名や本人確定の根拠にはしません。発話中の名前と対応する会社の手掛かりから調査対象を補正した場合も補正を表示し、取得した一次資料で本人への帰属を改めて検証します。会社が食い違う場合は勝手に置き換えず、候補を確認するか名前を言い直します。日本語会話・G2の実機動作は未検証です。

ログイン用QRは単回・最大10分の方式に加え、指定期限まで再利用する方式を用意しています。再利用QRは最大48時間・有効なもの5枚までで、再利用しても期限を延長しません。発行時は認証に加えて利用コードを再確認し、QRを受け取った人はコード入力なしで使えます。会話認証は無操作15分・開始から最大12時間で、QRに短い期限がある場合はそれを超えません。端末の認証記憶も最大12時間とQR期限の早い方までです。QR失効は以後のログイン交換を止める操作で、既存端末の認証記憶を一括削除する操作ではありません。[詳しい使い分け](docs/RUNNING.md#ログイン用qrの使い分け)。

会話開始時は人物一覧を表示し、認識した人物を順番に追加します。調査完了では自動遷移せず、選んだ人の質問と出典だけを開きます。「最新の調査を表示」も一人を明示選択する操作で、別人物へ自動追従しません。人物一覧はページのメモリ内で最大15分・30人までで、停止・背景移行・終了時に消去します。選択だけでは再検索・録音リセット・人物固定をしません。G2の人物一覧は上下で選び1回で開きます。質問画面の2回タップは一覧へ、出典画面の2回は質問へ戻ります。移動や音声操作の確認中は1回で実行、2回で取消だけ。人物固定はスマホのボタンに残します。[仕様10・検証状況](docs/specs/10_PERSON_HISTORY_AND_NAVIGATION.md)。質問の自然さと音声操作の分離は[仕様08](docs/specs/08_RESPECTFUL_QUESTIONS_AND_EXPLICIT_AUDIO_CONTROLS.md)を引き継ぎます。

## 段階表示

調査は確認済みの速報を先に用意し、過去のX投稿・Facebook・Instagramが届いた順に更新します。会話中は一覧の状態を更新し、選択中の人物についてだけ質問へ反映します。会話と次の人物抽出は継続し、対象が変われば旧要求から遅れて届く結果を破棄します。すでに確認した結果は人物一覧の期限内で再表示でき、閲覧中の人を別人物の結果へ置き換えません。追加情報の失敗だけでは速報を消しません。SNSはサーバー設定の `APIFY_ENABLED=true` と `APIFY_API_TOKEN` で有効化し、確認済みアカウントのみ取得します。速報の4枠は従来のX配分を優先し、SNS取得後は1枠をSNSの話題に更新します。詳細は[段階表示の仕様・検証](docs/specs/04_PROGRESSIVE_RESEARCH.md)。

## AI-DLCの進め方

公式2.9.0の導入スクリプトを同梱しています。ローカルで公式MVPフローを開始しましたが、現在のエンジン状態はintent-captureで、後続段階の完了は記録していません。今回の実装は、ユーザー確認済みの要求・設計・検証計画と開発委任に基づくConstruction作業です。公式の承認履歴を遡って作成しません。[実装記録](docs/validation/MVP_IMPLEMENTATION.md)。

初回は各自の `aidlc`、Codex hooks、診断を[導入ガイド](docs/AI_DLC_SETUP.md)に沿って準備します。公式配布物の全量複製は同梱せず、公式の状態・監査情報と独自の検証記録を区別します。

リポジトリ：[ima-work-git/ai-hack-agent](https://github.com/ima-work-git/ai-hack-agent)

## 最初にすること

1. [準備チェックリスト](docs/PREPARATION.md)で担当者と未決定事項を埋める。
2. [GitHub・チーム運用](docs/TEAM_AND_GITHUB.md)に沿ってこのリポジトリへ参加し、招待受諾・clone・練習PRを確認する。
3. [AI-DLC導入](docs/AI_DLC_SETUP.md)を読み、`sh scripts/setup-aidlc.sh` で各自の端末へ公式2.9.0を導入する。
4. [Even G2連携](docs/EVEN_G2_INTEGRATION.md)で既存方式と未検証箇所を確認し、[課題・要件](docs/specs/01_INTENT_AND_REQUIREMENTS.md)のMVPと受入条件に沿って実装する。
5. [エージェント設計](docs/specs/02_AGENT_DESIGN.md)で自律実行・人の承認・失敗時の動きを決め、1本の業務を最後まで通す。

**開発時の人間の承認と、完成したエージェントの利用者承認は別です。**
AI-DLCでは人が重要な開発判断を行います。プロダクト側では、どの操作をAIだけで進め、どこで人に戻すかを仕様化して審査で説明します。

## このリポジトリの使い方

- `docs/specs/` は事前検討用。公式ワークフローを起動したら採用済み内容を入力し、生成された仕様へのリンクを残す。二重に仕様を更新しない。
- 公式ワークフローの出力先・管理対象は[導入ガイド](docs/AI_DLC_SETUP.md)に従う。
- `.github/` にはIssueフォーム、PRテンプレート、資料チェック用のCIがある。
- `.env.example` は設定項目のひな形。実際のキーは `.env.local` など、Git対象外のファイルに保存する。
- アプリは `src/`、サーバーは `server/`、自動試験は `tests/`。公開デプロイURLは未作成。

資料のローカルリンクと追跡ファイル名の確認：

```sh
python3 scripts/check_preparation.py
```

この確認は仕様内容の承認、アプリのテスト、秘密情報の全検出を代替しません。
提出期限はユーザー提示の「9月22日15:00」。年・タイムゾーンを主催者に確認するまで、計画上は2026年9月22日15:00 JSTを仮置きします。
