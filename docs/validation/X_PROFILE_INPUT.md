# Xプロフィール入力の検証と修正

実施日：2026-09-22。公開Xプロフィールを対象に通常の調査が通るか、という依頼から検証しました。特定人物の分岐や成功済みの固定カードは追加していません。

## 発見・修正

1. URLに含まれるアカウントを認識しない問題：HTTPSの`x.com`/`twitter.com`の公開プロフィールURLを、明示`@handle`と同じ識別子として抽出。偽装ドメイン、資格情報、ポート、投稿/予約パスは対象外。大文字小文字の違いと重複を整理し、複数の異なるアカウントは確認で停止。
2. 追加検索も同じXタイムラインを読む問題：初回のみ指定アカウントを優先し、追加は対象の氏名と会社によるWeb検索へ進める。
3. Xの5投稿で全本文枠を消費する問題：初回最大2本文、合計最大4本文として、追加のWeb本文取得に枠を残す。5投稿を返す合成API応答でも、Web本文を取得し、その出典のカードを返す回帰試験を追加。

URL/ハンドル単独は、氏名・所属が不明なので確認待ちになります。この場合はローカルで判断し、OrcaRouter/Xへ送信しません。氏名・会社の入力照合と、本文中の本人・所属・引用検査は維持しています。

## 証拠と限界

最終ローカル検証：型・資料リンク・本番ビルド成功、全287テスト成功、集計対象の行カバレッジ95.33%。独立レビューでも初回5投稿から追加Web本文へ進むことを確認しました。

- 合成データでURL抽出、偽装入力の拒否、URLだけの確認待ち、X→Web、5投稿時の取得枠、未指定アカウント創作の拒否を検証。
- 指定対象の公開ブログと所属先の公式プロフィールは、実際のアプリのWeb取得処理で本文を取得できました。本文内の表記一致も調べましたが、文字列の一致だけで本人・所属が意味的に検証できたとは扱いません。実在者の本文や固定カードはテストデータへ転載していません。
- 日本語名と英語名、愛称と本名の自動対応は未実装です。一致しない表記の資料を推測で採用しません。
- ローカル設定のOrcaRouter・Web検索・Xキーと費用上限が未設定のため、実LLM/X APIでの通し検証は未実施です。課金呼出しはしていません。実APIで出典付きカードが返ること、およびG2表示の合格とは別です。

次の通し試験では、氏名・会社・公開アカウントを明示し、通常のliveモードで実行します。検索/本文/LLMの呼出数、出典と対象一致、途中の確認や失敗、実費留保を確認し、失敗を固定出力で隠しません。
