# 実行・設定・復旧

> 2026-09-23 更新：質問は「⭐️推奨質問：」で表示。G2の質問・出典本文は14px画像にし、収まらない全文や画像非対応・明示拒否時は標準文字へ戻します。人物一覧・音声状態は標準文字を維持します。画像転送の応答が失われた場合は従来どおり停止して再接続を案内し、遅延した操作と新しい操作を重ねません。QR認証は表示中に実行します。


## まず架空データで動かす

Node.js 24、`npm ci` → `npm run dev` → `http://localhost:4173`。
「架空の会話を入力」から通常／同姓同名／検索障害／根拠なしを確認できます。デモ結果は実APIや実機の証拠ではありません。

本番相当のローカル配信は `npm run build` → `npm start`。サーバーの同一originから画面とAPIを配信します。

## 実APIを有効にする

`.env.example`を`.env.local`へコピーします。鍵をこのリポジトリ、ブラウザー用の`VITE_*`変数、記事、スクリーンショットに含めないでください。

1. `APP_ACCESS_CODE`に16文字以上の利用コードを設定。
2. `ORCAROUTER_API_KEY`、構造化出力対応の`ORCAROUTER_MODEL`、`TAVILY_API_KEY`を設定。質問生成と根拠評価だけ別モデルにする場合は`ORCAROUTER_ASSESSMENT_MODEL`を指定します。空欄は従来モデルを使い、計画・音声認識・人名補正のモデルは変わりません。モデルを分ける場合も`MAX_LLM_CALL_USD`は両モデルの最大入出力費用を覆う額に設定します。
3. USDの1回／1日／大会全体の予算、およびLLM・検索・本文取得の最大見積額をすべて設定。無料の直接ページ取得は`MAX_PAGE_CALL_USD=0`を明示。
4. 必要ならX読取トークン、`X_API_ENABLED=true`、`X_MAX_SEARCH_COST_USD`にユーザー1件＋最新投稿最大5件＋過去投稿最大20件＋空タイムライン時の追加候補最大10件を保守的に合算した最大見積額を設定。`X_BALANCED_TOPICS`は既定で`true`。自分の開発アカウントが検索対象になるわけではありません。
5. 設定を確認して`AGENT_LIVE_ENABLED=true`、サーバーを再起動。画面で利用コードを入力し「実APIで調査」を選択。

モデル名や価格は固定の推測値を置いていません。選択モデルの最大入出力と現在のサービス料金から、1操作の最大額を保守的に決めます。料金が確定していない場合、成功・失敗とも予約を残します。OrcaRouterのレスポンス中のcost_usdは暫定報告額なので、画面に別表示し、留保額を減らしません。予算ファイルを消して課金制限をリセットしないでください。X利用可能・チャージ済みという申告と、鍵の実接続成功は別です。

OrcaRouterは [Chat Completions](https://docs.orcarouter.ai/api-reference/chat/create-a-chat-completion) と [構造化出力](https://docs.orcarouter.ai/advanced/structured-outputs) を使用します。モデルが非対応ならエラーで止まり、無制限な修復や勝手なモデル変更をしません。

Tavilyはbasic検索を最大5結果に固定します。検索抜粋をそのまま根拠にせず、実際の本文を取得します。JavaScript必須ページ、ログイン壁、Facebook、Xの直接スクレイピングには対応しません。Xは入力に明示した`@handle`、HTTPSの`x.com`/`twitter.com`プロフィールURL、または公開一次資料で対応を確認した人物だけを公開APIで調べ、保護アカウントを拒否します。会社名なしの公開人物として「ひろゆき」→`@hirox246`、「ホリエモン」→`@takapon_jp`を扱い、「ちょまど」→`@chomado`も会社名なしで利用します。明示された会社名がある場合は、その一致を別途確認します。会社名がないことだけでは停止せず、他の公開人物も一般Web検索で調べます。ひらがな・カタカナの表記差は正規化しますが、任意の漢字の読み・日英表記・愛称を推測して同一視したり、Xアカウントへ必ず解決したりしません。別名対応は新しい事実や現在の雇用関係の証明には使いません。URL・ハンドルだけなら調べたい人物名の確認へ戻り、同名候補や帰属が曖昧な場合も確認します。初回だけXを優先し、追加調査はWebへ進みます。Xの投稿ページは追加でめくらず、タイムラインが空の場合に限る下記の検索で補い、それでも根拠が不足すれば残りの検索枠でWeb調査へ切り替えます。従来経路では追加のX検索を行いません。通常・従来経路の本文取得枠は初回最大2件・全体最大4件とし、追加調査の枠を残します。Xの4枠構成では下記の最大6資料を使います。取得した文書タイトルと本文から短い引用候補を作り、AIが人物との関係を評価して候補文のIDを選びます。事実・引用は原文から復元し、AIの言い換えを根拠として採用しません。

## Xの4枠構成と選定範囲

X有効時は`X_BALANCED_TOPICS=true`を既定とし、最近Xを2件、過去Xを1件、人物・会社を1件優先します。`false`では従来のユーザー照会＋投稿最大5件の経路へ戻ります。全期間検索の利用権限がない等で過去投稿を取得できない場合は、取得済みの検証可能な話題に縮退します。

- **最近X**：対象アカウントの最新投稿を最大5件取得し、リポストと返信を除きます。タイムラインのAPI応答自体が空の場合だけ、全期間検索の`sort_order=recency`で最大10候補を一度取得し、最新5件までを候補にします。安全性検査で投稿を除外した結果の空欄には、この追加取得を行いません。追加取得のページ送り・再試行はしません。「最近」は最新順の意味で、7日以内という保証ではありません。投稿日をスマホの詳細に表示します。
- **過去X**：2006-03-21から実行時の7日前までを[全期間検索](https://docs.x.com/x-api/posts/search/quickstart/full-archive-search)し、`sort_order=relevancy`の最大20件だけを取得。最新側との重複を除き、いいね＋リポスト＋引用の合計で候補を順位付けします。返信数は表示しますが順位には含めません。ページ送りで全投稿を走査せず、表示は「過去の反響：全期間の検索候補から選定」とします。
- **人物・会社**：公開プロフィールと実際に取得した会社公式資料等を使います。取得済みXユーザーの投稿者IDと確認済みアカウント対応を照合できる場合は、会社との関係を公式Web資料で補えます。投稿カードの事実そのものは、その投稿本文の原文からのみ採用します。

最初にX資料を最大4件（プロフィール＋投稿3件）、追加Webを最大2件、全体で最大6資料を評価します。通常・従来経路は全体4資料のままです。本人確認に参照する資料IDも最大6件まで受け入れ、すべて取得済み本文と照合します。根拠評価のみ最大12秒、それ以外の個別操作は8秒です。検索2回・LLM3回・対象調査全体20秒は変更しません。2:1:1を満たせなくても別種類の検証済み話題は実際のラベルで表示し、それも不足すれば4件未満とします。

Xの1回の検索処理は、ユーザー照会・最新タイムライン・過去検索の通常3回に、空タイムライン時の追加検索を含めて最大4回のHTTP呼出です。予約はユーザー1件と投稿最大35件（5＋20＋追加10）を保守的に合算した計36リソースで見込みます。2026-09-22確認の[公式料金](https://docs.x.com/x-api/getting-started/pricing)で単純計算すると`$0.010 + 35 × $0.005 = $0.185`です。これは予約額を決めるための見積りで、請求確定額や価格上限の保証ではありません。最新料金を考慮した保守的な額を設定し、実請求が不明な予約は解放しません。

## デモ・開発期間だけ費用上限を解除する

利用者が明示的に指定した期間だけ、`BUDGET_LIMITS_SUSPEND_FROM`と`BUDGET_LIMITS_SUSPEND_UNTIL`にタイムゾーン付きISO日時を設定し、サーバーを再起動します。開始以上・終了未満の最大48時間、1調査・1日・イベント全体の金額による停止だけを解除します。既定は両方空で通常上限です。片方だけ・不正日時・48時間超は起動時に拒否します。

通常上限と1呼出の最大見積額は引き続き設定が必要です。実費・未確定費用の予約・累積記録は保持し、回数・時間・認証・同意・セキュリティ制限は維持します。終了日時からは再起動なしで次の予約に通常上限を適用し、解除期間の累積額も含めて判定します。記録を消して予算をリセットしません。外部API側の残高・制限は解除しません。

## 利用コードの入力を省略する

初回は利用コードを入力します。「この端末では12時間、利用コードの入力を省略する」は既定でオンです。記憶させたくない端末ではチェックを外してください。利用コードで作る記憶の期限は最初の発行から12時間で、再訪や自動再認証によって延長しません。再利用QRから作る記憶は、発行から12時間とQRの指定期限の早い方までです。

記憶するのはランダムな端末認証トークンだけです。会話用とは別のCookieに保存し、`HttpOnly`・`SameSite=Strict`、HTTPSでは`Secure`を設定します。サーバーの`.private/`配下には、そのハッシュと有効期限だけを保存します。利用コードやAPIキーをブラウザーの永続領域、QR、G2パッケージへ保存しません。

有効な記憶があれば、画面を開いた際のPOSTによる復元処理で自動再認証し、新しい短期Bearerを取得します。会話認証は無操作15分で失効します。明示開始した会話中だけ接続確認で更新し、開始から最大12時間、またはQR等の短い期限で終了します。会話データの最大15分の保持窓は認証延長で延ばしません。前の結果は「前の内容を再開」を押したときだけ表示し、録音や有料調査を自動で再開しません。「終了して削除」は会話を削除し、この端末の記憶もサーバー側で失効させます。利用コードを変更した場合も、以前の記憶は無効になります。

SafariとEven Appは別の保存領域を使うため、それぞれで初回認証が必要です。Even AppのWebViewがCookieを保持することは実機未確認です。Cookieが消えた場合や期限を過ぎた場合は、利用コードを再入力するか、有効なログイン用QRを開き直してください。

## 音声

会話モードにはサーバー側の`OPENAI_API_KEY`と、音声認識1分あたりの保守的な最大見積額`STREAMING_ASR_MAX_USD_PER_MINUTE`を設定します。`OPENAI_STREAMING_ASR_MODEL`の既定は`gpt-live-transcribe`で、現実装はこのモデルに対応します。鍵や最大見積が未設定なら会話モードは無効です。音声認識はOpenAIの[Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription)へサーバーから直接接続し、人物抽出・調査計画・根拠評価・質問生成にはOrcaRouterを使います。OpenAIの鍵はOrcaRouterの鍵とは別で、どちらもブラウザーへ渡しません。

通常の短い録音には`ORCAROUTER_STT_MODEL`に[input_audio対応モデル](https://docs.orcarouter.ai/advanced/audio-input)、`MAX_STT_CALL_USD`に1回の最大額を設定します。または`STT_API_BASE_URL`・`STT_API_KEY`・`STT_MODEL`をすべて指定したOpenAI互換STTを使用できます。明示STTが優先、部分設定なら停止です。この設定だけでは会話モードは有効になりません。

利用前に会話相手への説明・同意を済ませる運用です。毎回の同意チェックボックスは使いません。専用の会話用QRをEven Appで読み取った場合は、その操作を開始要求として認証・G2・ASR準備後に一度だけ会話を開始します。通常ページからは「実APIで調査」と入力元を選び、「会話モードを開始」を押します。G2を選んで接続できない場合はスマホへ自動切替しません。アプリが第三者の同意を取得したという記録は作りません。[QR開始の条件](specs/09_QR_CONVERSATION_START.md)と[事前同意の運用](specs/08_RESPECTFUL_QUESTIONS_AND_EXPLICIT_AUDIO_CONTROLS.md#同意済みの利用条件)。会話モードでは16 kHz・mono・PCM16を同一originのWebSocketへ逐次送信し、サーバーで24 kHzへ変換してOpenAIへ送ります。原音をディスクへ保存しません。

1. 会話用QRからは準備完了を待ち、通常ページでは「会話モードを開始」を押します。「聞取中」になってから話します。30秒では停止せず、話している途中から認識文字を表示します。約5秒ごとに音声区間を確定し、その発話から調べたい人物名を抽出すると調査を始めます。会社名は判明した場合に絞り込みへ使い、公開人物の調査では必須にしません。複数人物や人物の特定に必要な情報が不足する場合は確認へ戻ります。
2. 事実と質問を最大4組、同じ画面で確認します。未確認の枠を推測で補いません。省略記号で切らない短い表示文を使い、スマホでカードを押すか「前の出典」「次の出典」で全文・引用・URLを確認できます。
3. 「会話モードを終了」または「中止」で止めます。「終了して削除」は会話と端末の認証記憶も削除・失効させます。通常の短い音声入力は従来どおり最大30秒で、停止後に一度だけ認識・調査します。

会話モードは音声認識と調査を別の接続で進め、調査中も音声を送り続けます。人物抽出・調査は直列で、遅れた場合は最新の確定発話だけを次に処理します。同じ氏名と会社名（未指定なら空）の組は120秒、結果がない場合は30秒の再検索を抑制します。G2マイクはASR接続準備完了後に開始します。スマホは許可取得のため先に開始しますが、接続準備中のPCMを破棄します。準備完了後の短い音声配送の偏りは固定容量の待ち行列と送信ペースの調整で吸収し、それを超える送信遅延は停止します。旧来の12秒窓・8秒間隔の録音送信は、現在の会話モードには使いません。

会話中の接続確認で無操作15分の認証期限を更新し、開始から最大12時間（QR等に短い期限があればその期限）で終了します。人物抽出・調査は直列で、要求履歴は最新100件に制限します。会話データは最大15分の固定した保持窓で削除し、新しい調査や接続確認で古いデータの期限を延ばしません。ストリーミング音声の送信量と接続経過時間の大きい方を基準に、1分単位の上限額を先に予約します。人物抽出・調査も同じ会話の承認済み予算へ集計し、料金未確定の予約を解放しません。通常の短い録音はWAVを一度だけ送り、STTと直後の調査で同じ要求UUIDの予算を共有します。対象調査は20秒、人物抽出と必要時の名前補正を合わせて最大16秒、個々の補正と短い録音のSTTは各8秒の上限です。

停止・終了、画面の非表示、切断、ページ離脱、ログアウト、認証・費用の上限で停止します。会話相手の意向が変わった場合も停止してください。復帰しても録音や有料処理を自動再開しません。すでに送信済みの外部サービス処理まで撤回できるとは保証しません。2026-09-22にPCから公開英語サンプル8秒を送った接続試験では、最初の増分を約0.94秒で受信し、増分7回・確定1回を確認しました。日本語会話、スマホの実際の音質、G2実機の検証を代替する結果ではありません。

### 聞き間違いと人物の確認

明示開始した会話が続き、画面が表示されている場合だけ60秒ごとに接続を確認して認証の無操作期限を更新します。画面の非表示中や会話の終了後は更新しません。

公開一次資料に基づく15人の氏名・公開名・読みを拡張可能なカタログで管理します。「広行」のような音声認識の誤記は訂正候補として分離し、確認済み別名や本人確定の根拠にはしません。発話中の名前と対応する会社の手掛かりから調査対象を補正した場合も補正を表示し、取得した一次資料で本人への帰属を改めて検証します。会社が食い違う場合は勝手に置き換えず、候補を確認するか名前を言い直します。 公開カタログにない人物は一般Web検索で調べます。西村博之と「株式会社made in Japan／株式会社メイドインジャパン」の関係は[会社の公式情報](https://modein.co.jp/corp/)を確認して登録しています。会社付きの調査では、取得本文にも名前と対応する会社の記述が必要です。

人物の補正には、`OPENAI_API_KEY`がある場合は既定でLunaを使います。`PERSON_CORRECTION_ENABLED=false`で追加の補正呼出を無効にでき、`PERSON_CORRECTION_MODEL`の既定は`gpt-5.6-luna`です。候補や根拠が不足すれば確認待ちとなり、会話中は次の発話を待ちます。「聞き直す」は前の対象・結果・待機中の発話をリセットし、音声接続を維持したまま新しい名前を受け付けます。録音の明示終了や非表示・切断による停止とは区別します。

## Even G2

既存アプリと同じEven Hub SDK 0.0.12のWebViewブリッジを使います。質問・出典本文は14pxで576×144内に描画し、左右288×144のPNGを順番に送ります。質問4組は間隔を空け、「⭐️推奨質問：」で区別します。全文が収まらない場合は文字を削らず標準表示へ戻し、次の短い画面では小文字表示を再試行します。画像非対応・明示拒否時はその接続中の標準表示を維持します。転送タイムアウトは安全に取り消せないため、停止して再接続を案内します。人物一覧、ヘッダー、音声状態は標準文字のままです。スマホの質問番号選択は出典詳細を切り替え、選択中の人物のG2質問画面を維持します。G2の出典移動は確認を表示してから実行し、同じタップで音声をリセットしません。不足は「未確認」とします。SDK受付の成功とグラス上で読めることは区別し、実機の読みやすさは確認が必要です。

会話用QRは`?conversation=1`とQR用の`#login`フラグメントを伴います。今回のQRを読み取る操作を開始要求として、端末認証が記憶されていてもQRをサーバーで検証し、成功後に実APIモード・G2接続・ASR準備を待って一度だけ会話を開始します。人物・会社の事前登録や開始ボタンの追加操作は不要です。会話相手への説明・同意は利用前に済ませます。クエリだけのURL、無効QR、通常ページ、更新・履歴復帰、端末認証復元だけでは開始しません。[仕様09](specs/09_QR_CONVERSATION_START.md)。

準備中に「中止」や「終了して削除」を押した場合、画面を隠した場合やページを離れた場合は、保留中の開始要求を取り消します。後から認証・接続・ASR準備が完了しても開始しません。G2未対応の外部ブラウザーではEven Appで開く案内を示します。スマホマイクへ自動切替せず、スマホ利用時のiOS・ブラウザーの許可や開始操作を迂回しません。今回のQR自動開始と実機の改善は[検証記録](validation/QR_CONVERSATION_START.md)で確認状況を分けます。

「使うマイク」でEven G2／スマートフォンを明示選択します。会話用QRではG2を初期選択し、未接続なら接続を試みます。G2に接続できない場合は開始せず、スマホへ自動で切り替えません。入力元はグラス下部にも表示します。 確認なしの1回タップでは音声を操作しません。質問画面の上スクロールから「聞き直す／音声を再開」を確認し、1回で承認、2回で取り消します。確認のない2回タップは質問画面から人物一覧、出典画面から質問へ戻ります。人物一覧の上下は選択移動、1回でその人を開きます。固定はスマホの明示ボタンを使います。システム終了は音声を停止します。

調査結果は途中を「…」で切る方式から、短く完結した表示へ変更しました。既存の根拠評価と同じ呼出内で、原文に実在する28字以内の句と26字以内の質問を作り、原文との一致・省略記号・否定や時制の切り落としを検査します。原文の事実・引用・出典はそのまま保持します。安全に短縮できない場合は元の全文を使い、文字を削除しません。14px画像に全文が入らない場合は標準表示へ戻します。追加のAPI呼出は行いません。

会話中はG2下部に入力元（G2／スマホ）、音声接続中・聞取中・調査中・停止・エラーを表示します。聞取中は直近の認識文字も表示し、話題4組を維持したまま最大0.5秒ごとに更新します。同じ本文画像を再送しないため、認識状況の更新でBluetooth転送を増やしすぎません。停止後は認識文字を消し、遅れて届いた音声イベントは表示しません。

現在の確認経路は、UIとAPIを同じoriginで配信するサーバーをEvenアプリのローカルテストQRから開く方式です。スマホからlocalhostは開けません。端末から届くサーバーの`HOST`・`APP_ORIGIN`を設定し、発行者は利用コードで認証します。通常QRにはアクセス先だけを含めます。LANに開く場合も鍵や保存データの公開は禁止です。実APIを使う配信はHTTPSにしてください。

```sh
npm run build
npm run pack:g2
```

`.ehpk`は静的画面の梱包確認用で、Nodeバックエンドを含みません。配布版にはHTTPSバックエンドURL、manifestのnetwork whitelist、WebView originに対応するCORS・認証・Cookie再開の検証が必要です。現時点で「このパッケージだけでG2の調査が使える」とは扱いません。min_app_versionは設定値であり、実対応確認済みではありません。[公式ローカル試験](https://hub.evenrealities.com/docs/test/local-testing)・[通信権限](https://hub.evenrealities.com/docs/build/networking)。

## ログイン用QRの使い分け

ログイン用QRは、初回の利用コード入力を省略する専用トークンをURLフラグメントに含めます。APIキー・利用コード・端末記憶用トークンは含めません。QRの発行は管理操作で、認証済みBearerに加えて、単回・再利用のどちらもリクエスト本文の`accessCode`で利用コードを再確認します。受け取った人はコードなしでログインできますが、QRだけで新しいQRや延長期限を発行できません。

| 方式 | 期限と再利用 | 発行元・再起動との関係 |
| --- | --- | --- |
| 単回QR | 最大10分、1回交換すると失効。フラグメントを起動時に削除 | 発行元の終了・期限切れ、サーバー再起動でも失効 |
| 再利用QR | 発行から最大48時間以内の指定期限。有効なQRは最大5枚。再読取で延長しない | 発行元のログアウト・期限切れ、サーバー再起動に依存しない |

再利用QRは認証付き`POST /api/session/qr/reusable`で発行し、本文に`accessCode`と`expiresAt`（UTCのISO形式、末尾`Z`）を指定します。期限は未来かつ発行時点から48時間以内です。サーバーの非公開領域にSHA-256のトークンハッシュ・期限をHMAC付きで永続保存し、生トークンは保存しません。利用コードの変更でも既存QRは無効になります。

交換は同一originの`POST /api/session/qr/redeem`で行い、無操作15分で失効する新規の空セッションを作ります。明示開始した会話は接続確認で更新できますが、開始から最大12時間、またはQR等の短い期限を超えません。QRのフラグメントは起動時に読み取ってURLから除去します。同じQRを読み直すと再交換できます。端末の認証記憶は「発行から12時間」と「QR期限」の早い方までに固定します。通常のログイン用QRはマイクを開始しません。`conversation=1`を伴う会話用QRでは、今回のQR交換成功後の一度だけ、G2・ASR準備を待って開始します。会話終了や無操作による失効は、再利用QRそのものの期限を延ばしたり短くしたりしません。

認証付き`DELETE /api/session/qr/reusable`に対象の`ticket`を渡すと、そのQRによる**今後の新規交換**を失効させます。すでに作成された会話セッションや各端末の認証記憶まで一括失効する操作ではありません。その端末の会話と記憶は「終了して削除」で失効させます。Even Appでの再読取・フラグメント・Cookie保持は実機確認が必要です。

## 保存と復旧

- `.private/sessions/`はAES-256-GCMで暗号化。鍵は`.private/.session-key`、端末のファイル権限で保護します。鍵と暗号文を同時に盗まれた場合まで保護する設計ではありません。
- 会話認証は無操作15分、会話中の延長を含め開始から最大12時間（QR等に短い期限があればその期限）。会話データは別の最大15分の保持窓で削除します。明示終了で個人データとその端末の認証の記憶を削除・失効させ、期限切れも掃除します。端末記憶や接続確認は会話データの保持期間を延ばしません。再認証でBearerを更新し、前の結果は「再開」操作後のみ表示、マイクや有料調査は自動再開しません。
- 中断時は手動で再調査します。遅れた旧結果は破棄。G2のSDK応答不明や切断時はスマホへ縮退し、実機の残留表示が消えたと断定しません。再接続は明示操作です。
- 429・5xx・本文取得失敗は残る情報へ縮退します。同じ外部操作の無条件再試行はせず、上限内で別資料や追加調査を選びます。未確認の事実は表示しません。
- 予算記録は匿名UUID・UTC日次集計。再起動しても予約を維持。残ったロックや破損ファイルはfail-closedで止めます。実行プロセスが残っていないこととサービス明細を確認してから復旧してください。
- 既定は端末内のみで起動します。OrcaRouter・Tavily・Xの実API疎通とPCからの公開英語サンプルによるストリーミング接続は確認済み。日本語会話・G2実測・実費照合は未完了です。

## 段階表示と追加SNS

最近のX投稿とプロフィールを先に検証・表示し、過去Xと追加SNSは後から更新します。Instagram/Facebookを使うには、非公開のサーバー環境に `APIFY_ENABLED=true` と `APIFY_API_TOKEN` を設定して再起動してください。未設定でもX/Webの調査は利用できます。本人リンクが確認できていないアカウントを同名だけで登録しません。

追加調査の失敗では速報を保持します。停止・対象変更は取得を中止し、古い応答は破棄します。APIの開始結果が通信断で不明な場合は再送せず、60秒の外部実行期限と各$0.10の上限を残します。設定を無効にして再起動すればSNS取得を止められます。[受入条件・時間と回数の制限](specs/04_PROGRESSIVE_RESEARCH.md)。

## PC復帰後も同じQRで開く

固定入口を使ったQRに一度差し替えると、トンネルURLが変わっても同じQRで期限内に再開できます。macOSの専用LaunchAgentでログイン時の起動と接続復旧を行います。PCスリープ中は利用できず、QRの認証期限も自動延長しません。[設定・復旧の仕様](specs/05_STABLE_QR_RECOVERY.md)。

## 認識人物の一覧・質問・出典

会話から抽出した人物と判明した会社を、認識した順に下へ追加します。スマホには人物ごとのボタンと「人物一覧に戻る」を表示します。同じ人物・会社の再認識で順番は変えず、同名別会社は別項目にします。複数の候補を認識したときは全員を未確認として残し、自動で1人を本人と断定しません。

会話開始時は人物一覧を表示します。認識や調査が進んでも一覧に留まり、人物を選んだときだけ質問を開きます。「最新の調査を表示」も、その時点の最新の調査結果に対応する人物を一度選ぶ操作です。別の人物を認識したり、その結果が追加されたりしても閲覧先は切り替えません。人物を選ぶだけで音声をリセットしたり、固定したり、有料検索をやり直したりしません。未調査の項目は「未確認／名前を言い直してください」などを表示し、確認できたカードだけを出典付きで再表示します。

| G2画面 | 操作 | 動作 |
| --- | --- | --- |
| 人物一覧 | 上下／1回／2回 | 上下で選択、1回でその人の質問へ、2回は一覧に留まる |
| 質問画面 | 確認なし2回 | 人物一覧へ戻る |
| 質問画面 | 下／上スクロール | 下は出典移動、上は聞き直し／音声再開の確認 |
| 出典画面 | 確認なし2回 | 同じ人物の質問へ戻る。もう一度2回で人物一覧へ |
| 出典画面 | 上下スクロール | 前後の出典や質問画面への移動確認 |
| 確認中 | 1回／2回 | 1回で表示中の操作だけ実行、2回で取消だけ |

確認中の2回タップで取消と戻るを同時に行いません。戻るには取消後に改めて2回タップします。確認なしの1回タップは音声を操作しません。スマホの質問番号でSNS名・該当文・取得した元投稿・リンクを確認できます。取得できていない本文は補完しません。3回タップ・長押しの専用操作は前提にしません。

人物固定はスマホの「この人物で固定」で行い、解除は「固定を解除して聞き直す」を使います。過去の人物の表示選択とは別操作です。音声を止める場合はスマホの「中止」「会話モードを終了」、またはホストの終了操作を使います。

一覧と再表示用の結果はページのメモリだけに保持し、各項目は初回認識から最大15分、最大30人までです。追加取得・再認識・閲覧で期限を延長せず、カード自身のより短い期限も守ります。31人目以降は古い項目から除去します。停止・背景移行・切断・ログアウト・期限切れ・新会話で一覧を消し、遅い結果から復元しません。選択中の項目が消えた場合は一覧／待機表示へ戻し、別人を自動で開きません。[仕様10](specs/10_PERSON_HISTORY_AND_NAVIGATION.md)と[今回の検証状況](validation/PERSON_HISTORY_AND_NAVIGATION.md)を参照してください。

## 検索語と候補を確認する

「検索キーワード」に実際に送信する検索語やSNSアカウントを表示します。Xの最近投稿はアカウントの投稿取得、過去投稿は検索式、Instagram/Facebookは取得先プロフィールURLです。キャッシュ利用を新規検索とは表示しません。
