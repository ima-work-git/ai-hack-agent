# 継続音声とG2人物操作の検証

2026-09-23。[Issue #26](https://github.com/ima-work-git/ai-hack-agent/issues/26)、[仕様](../specs/06_CONTINUOUS_AUDIO_AND_PERSON_CONTROLS.md)。

## 観測と切り分け

ユーザー実機報告：ASR開始・認識に成功するが、使用中に「音声の送信速度超過・再開してください」と表示し、その後認識が止まる。今回は実機のPCM到着間隔を収集していないため、Bluetooth配送の偏りやクロック差が実機の唯一の原因だとは断定しない。

既存コードの再現：16kHz mono PCM16を、クライアントは到着直後にまとめて送信し、relayは32,000バイト/秒ちょうど・64,000バイトburstのバケットで判定していた。96,000バイト（3秒分）のまとめ配送と、32,400バイト/秒で5分継続する試験が変更前に失敗することを確認した。

## 変更

- クライアントは最大100msのPCMへ分割し、1.10倍以内の送信ペースと最大4秒の固定容量待ち行列で配送の偏りを吸収する。上限を超える遅延は停止する。
- relayは4秒のburstと1.15倍以内の速度を許容し、経過時間は単調時計で判定する。2倍など継続的な過送信は拒否し、送信したPCM量／接続経過時間を基準にする費用予約は維持する。
- 人物リセットではサーバーがPCM受理を止め、クライアントが待ち行列を消して同じWebSocket上に世代付きackを送る。最新ack前の旧PCMは破棄し、ack待ちにも期限を設ける。
- シングルタップとダブルタップを分離し、誤った人物のリセットと現在人物の固定を両立する。固定時もASRは継続するが別人物の抽出を止め、対象が同じ追加調査は受け取る。
- スマホの質問番号から出典詳細へ移動。SNS名、該当文、取得した投稿本文、リンクを表示し、G2では該当文を省略せずページ表示する。

## 確認結果

最終のチェック結果と公開版の配信確認は、この変更のPRへ記録する。テストは架空データ、モックのG2／APIと制御した音声・時計を使用し、新しい実機での連続使用成功を代替しない。

- main UIの110テスト成功：固定中のASR継続、別人物抑止、遅い抽出破棄、同一人物の追加調査、単一タップでエラー後再開、SNS本文のHTML非実行、該当文のページ表示など。
- G2 runtimeの46テスト成功：single/doubleの競合、省略されたCLICK=0、終了・背景・切断・再接続で保留イベント破棄。
- 継続音声の再現、量・順序・上限・reset世代の試験を追加。全33ファイル・933テスト成功。型・準備文書チェックと本番ビルドも成功。

独立レビューでは、reset通知だけでは送信中の旧PCMが混入する競合と、マイク停止ACK前の再開競合を指摘・修正した。世代付きACKと停止完了待ちの回帰試験を追加し、再レビューで追加の重大な指摘なし。

## 残る実機確認

更新版を開き直して数分以上のG2音声認識、実機の1回／2回タップ判別、出典ページの読みやすさを確認する。画面の公開配信と合成試験の成功だけで、iPhone/Even G2実機確認済みとは扱わない。
