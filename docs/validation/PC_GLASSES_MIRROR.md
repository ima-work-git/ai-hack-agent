# PCグラス表示ミラーの検証

2026-09-23。要求: [Issue #46](https://github.com/ima-work-git/ai-hack-agent/issues/46)、[仕様11](../specs/11_PC_GLASSES_MIRROR.md)。ユーザーの実装・レビュー・マージ委任を継続し、公式ワークフローの未実施の承認を記録しない。

## 実施結果

- 本番ビルド成功。既存の回帰検査を含む40ファイル・1,270テスト成功。
- サーバー側は既存Bearer認証と同一Originを要求し、PC閲覧は実loopback・ローカルHost・非プロキシ経由に限定。未認証投稿、公開トンネル、cross-site、不正payload、期限切れ、削除を確認。
- G2モックで、全コンテナの受付後だけ最新画面が通知されること、拒否時は通知しないこと、ミラー例外で表示処理が失敗しないことを確認。
- 送信処理の直列化・最新画面への集約・認証切替時の旧画面破棄・接続切断時の内容消去を確認。
- 独立レビューで切断時のPC残留を発見し、null表示と通信断中の保持上限を修正。PC側でも120秒で文字・画像・ARIA内容を消去する。追加3テストで空表示・HTML無害化・サーバー停止中の消去を確認。
- 稼働中の本番サーバーで認証済みテスト画面の送信とPCでの読み取りを確認し、終了時に消去を確認。公開トンネルの画面取得は403、アプリの公開接続は200。検証用画面を残していない。
- PCのブラウザーでライブ画面の受信待ち表示まで確認。スマホ側はQRの再読込が必要。

## 制約

自動試験はSDKの受付通知と通信・表示の検査であり、実グラスの光学画面との一致確認ではない。反映後、スマホでQRを再読込し、PCのライブ画面とグラスを見比べる実機確認は利用者が行う。新しい有料検索・推論APIは追加していない。

## 受信できないという実機報告後の修正

同日、ユーザーからグラスの文字がPCに表示されないとの報告を受けた。稼働APIは200だが最新フレームはnullで、PCへの実機データ到着は確認できなかった。コード監査で、500ms周期の音声フッター更新よりG2応答が遅い場合、毎回古い描画として扱われPC送信通知が抑止される不具合を確認した。

フッター更新を直列化し、待機中は最新だけ保持する。人物・本文・出典変更時は古い処理を即座に無効化する。700msのネイティブ応答と500ms周期の入力による再現試験で、発話継続中にもミラー通知が進むこと、人物切替時に旧画面を送信しないことを検証した。さらに初回描画前にも接続状態を送信し、HTTPエラーをスマホの「PC同期」に表示、送信待ち時間を6秒とした。

本番ビルドと41ファイル・1,276テスト成功。PC画面を更新済み。実機からの最終到着確認は、利用者がEven Appのアプリ画面を閉じてQRを再読込した後に行う。この修正で実際の未着原因すべてを確認できたとは扱わない。

追加で、保存したネイティブfetchをpublisherのメソッドとして呼ぶとWebViewで不正な呼出元になり得るため、globalThisを呼出元に固定した。呼出元が異なると例外を出す回帰試験を追加し、ミラー関連12テストが成功。「PC同期」をスマホ画面上部へ移動し、既存画面とのURL差分を持つ更新用QRを発行した。実機上のエラー詳細は取得待ちであり、回線の違いを原因とは断定していない。

更新QRでの再接続後、実機からの状態フレームを受信できた。state:error / reason:connect_timeout / view:nullを確認し、PC・スマホの別回線が直接の未着原因ではないことを確認。G2初期接続だけ待ち時間を10秒に延長し、マイク・操作の2秒は維持。3秒かかる初期接続とマイク期限の独立性を検証し、関連77テスト成功。PCおよびスマホにもG2の接続待ち時間切れを明示する。実画面の受信確認は継続中。

2026-09-23 12:07 JST、再接続後の実機からstate:recording / viewあり / 更新から830msのフレームを受信。PCのブラウザーでも「ライブ表示中」、人物の4件質問画面、音声認識中のフッターを確認した。PCとスマホが異なる通信回線のまま送信・受信できた。具体的な会話文や表示内容はこの検証記録に保存しない。光学的な文字サイズ・スクロール位置の一致は引き続き本機能の保証範囲外。
