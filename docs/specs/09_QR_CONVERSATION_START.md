# QR読み取りからの会話モード開始

2026-09-23のユーザー追加要求。追跡：[Issue #34](https://github.com/ima-work-git/ai-hack-agent/issues/34)。

ユーザーから「開始を押してもマイクは停止中でASRが始まらない」「QRを読み取った後は会話モードと音声認識を自動で開始したい」と報告・要求があった。前者の原因とG2実機での解消は、検証前に確定したと扱わない。

本仕様は、[仕様08](08_RESPECTFUL_QUESTIONS_AND_EXPLICIT_AUDIO_CONTROLS.md)の「QRだけでは開始しない」という開始条件を変更する。専用の会話用QRを読み取る操作自体を利用開始の意思表示とし、その後の開始ボタンを省く。事前同意の運用、通常ページからの明示開始、出典操作と音声操作の分離、停止・保持・本人性・費用の制約は引き継ぐ。

## 開始の流れ

1. ページ初回表示時に `conversation=1` と有効な形式のQR用 `#login` フラグメントが両方ある場合だけ、新しい開始要求を受け取る。トークンはURLから除去し、通常ページ・クエリだけのURL・更新・履歴復帰から開始要求を作り直さない。
2. 端末認証が記憶されていても、自動開始用QRのサーバー交換を優先し、有効性を確認する。交換成功後だけ開始を許可する。開始要求は認証を代替せず、形式が正しいだけの無効・期限切れ・失効済みQRでは開始しない。
3. 実APIモードとストリーミングASRが利用可能で、ページが表示中であることを確認する。G2を入力元として接続完了を待つ。
4. 条件がそろった時点で開始要求を一度だけ消費して会話モードを開始する。認証通知・G2接続通知が重複してもASR接続やマイクを二重に開始しない。
5. 音声認識サービスの準備完了後にG2マイクを開く。「音声準備中」「聞取中」などの状態を表示し、発話から人物・会社の抽出、調査、根拠付き話題の表示へ進む。

QR後の認証待ち・G2接続待ちを「聞取中」と表示しない。自動開始できない場合は、設定不足・接続不足・対応環境など次に必要な操作を利用者へ示す。成功を装った停止表示や、状態の分からない無限再試行にしない。

## 開始要求の有効範囲

| 状況 | 動作 |
| --- | --- |
| 今回読み取った会話用QRのサーバー交換成功、実API・ASR・G2が利用可能 | 準備後に一度だけ開始 |
| 同じ開始要求に認証・接続通知が重複 | 二重に開始しない |
| 通常URL、`conversation=1` だけのURL、更新・履歴復帰・ページ再表示、端末認証の復元だけ | 会話を自動開始しない |
| G2未対応の外部ブラウザー | Even Appで開く案内と手動の開始経路を示す。スマホマイクへ自動切替しない |
| スマートフォンのマイクを使う | 利用者が入力元と開始を選ぶ。iOSやブラウザーの許可・操作要件を迂回しない |
| 準備中の中止・終了・画面非表示・ページ離脱・ログアウト | 保留開始を取り消し、遅い認証・接続・ASR準備完了から開始しない |
| 開始後の停止・背景移行・切断・エラー | 既存の停止処理を実行し、自動再開しない |
| 新たに有効な会話用QRを読み直した場合 | 新しい開始操作として扱い、認証・接続条件を再確認する |

開始要求は、停止後の接続復帰や端末認証の復元だけで再び有効にしない。開始の途中で手動開始が選ばれた場合も一つの開始処理へ合流し、自動処理と手動処理で会話セッションを重複作成しない。スマホの「会話モードを開始」「中止」「会話モードを終了」「終了して削除」を維持する。

## 運用と保護

会話相手への説明・同意は利用前に済ませるというユーザー指定の前提を維持する。QR読取を利用者の開始操作として扱うことは、相手の同意をアプリが取得・確認した証拠にはならない。同意取得済みの監査記録を捏造しない。相手の意向が変わった場合は停止する。

QRの期限・最大48時間・失効、端末認証と会話認証の期限、最大15分の会話保持は延長しない。原音非保存、認証、費用計測・予約・設定済み制限、根拠と本人性の検証は継続する。QR開始後も検索対象がないうちに無関係な人物の有料調査を行わない。QRの秘密、音声、認識本文を公開ログや検証文書へ載せない。

## 受入条件

- **QR-01**：新しい会話用QRのサーバー交換成功と実API・ASR・G2準備後に一度だけ開始し、準備前にG2音声を送らない。端末認証の復元だけでQR検証を省かない。
- **QR-02**：通常ページ、クエリ単独、更新・履歴復帰、接続通知の重複、QR開始要求の消費後からは新たに開始しない。無効・期限切れ・失効済みQRは開始しない。
- **QR-03**：認証・G2接続・ASR準備の各待機中に停止／背景／終了した場合、後から応答してもマイク・ASR・調査を開始しない。
- **QR-04**：未対応ブラウザー・接続不可・ASR未設定を説明し、スマホマイクへ自動切替せず、OSの許可を迂回しない。
- **QR-05**：手動開始、停止、聞き直し、音声エラーからの明示再開を維持し、出典承認タップは音声へ影響しない。
- **QR-06**：認証・秘密の除去・期限・費用集計・保持期間の回帰を確認する。

HACK-01/05：QR読み取りを人の開始判断として、以後の人物抽出と調査はAIが進める。HACK-02〜04：意図しない復帰時の開始を防ぎ、準備失敗から案内・停止・再開始できる。HACK-06〜08と提出物の要件は変更しない。[検証記録](../validation/QR_CONVERSATION_START.md)で模擬試験と実機の結果を分ける。
