# 01 課題・要求・MVP — これで誰でも雑談マスター

> 2026-09-22 / v0.5。ユーザーが提示済み要件を確認し、開発・レビュー・マージを委任しました。追加要望の真正ストリーミング会話モード・4件同時表示を反映しています。[決定記録](../DECISIONS.md)。本書を開発の基準とし、公式AI-DLCの過去の承認・状態とは区別します。部分試験と未達は[実装検証記録](../validation/MVP_IMPLEMENTATION.md)を参照。日本語会話とG2の実機受入は未検証です。

## 採用した意図

サービス名は「これで誰でも雑談マスター」。懇親会・打ち合わせの立ち話で出た人名や会社名をEven G2で捉え、AIがWeb・利用可能な公開SNSを調査して、会話を深める短い話題を視界に返す。

対象利用者は対面の会話中に相手の背景を調べたい参加者。課題仮説は、スマホ検索による会話の中断と、相手の活動を知らず質問の機会を逃すこと。約2人でCodex・AWS AI-DLCを使用し、既存G2試作の接続・表示方式を引き継ぐ。

## MVP：1人について根拠のある話題を返す

音声処理の説明・同意確認と明示開始 → 短い音声区間から人名/会社名を抽出 → 対象照合（曖昧なら人が選択）→ 検索先を選択 → 公開情報収集 → 根拠照合、不足なら追加検索 → 最大4組の事実と質問を同時表示、または確認不能の表示。

継続会話モードは30秒で停止せず、マイクからの音声をサーバー経由でOpenAI `gpt-live-transcribe`へ逐次送信する。認識途中の増分を即表示し、約5秒ごとに音声区間を確定する。OrcaRouterが確定発話から人物名と判明した会社名を抽出し、公開調査と質問生成を行う。公開人物は会社名なしでも一般Web検索の対象とする。調査中も音声認識は別接続で継続し、人物抽出・調査は直列、遅延時は最新の確定発話だけを処理する。同じ氏名・会社の組は120秒、結果なしなら30秒の再検索を抑制する。会話中の接続確認で無操作15分の認証期限を更新し、開始から最大12時間（QR等に短い期限があればその期限）で終了する。人物抽出の要求履歴は最新100件に制限し、承認済みの設定予算を守る。会話データは別の最大15分の保持窓で削除し、認証延長で延命しない。従来の短い録音モードは最大30秒を維持する。

ひらがな・カタカナの表記差を扱い、公開一次資料で対応を確認した「ひろゆき」→`@hirox246`、「ホリエモン」→`@takapon_jp`、従来の「ちょまど＋Microsoft」→`@chomado`を検索に利用する。他の人物も事前登録なしで一般Web調査できるが、任意の別名の同定やXへの解決を保証しない。検索の開始と、本人への帰属を確認した情報の採用は別とし、曖昧な候補は人へ確認する。

公開一次資料に基づく15人の氏名・公開名・読みを拡張可能なカタログで管理します。「広行」のような音声認識の誤記は訂正候補として分離し、確認済み別名や本人確定の根拠にはしません。発話中の名前と対応する会社の手掛かりから調査対象を補正した場合も補正を表示し、取得した一次資料で本人への帰属を改めて検証します。会社が食い違う場合は勝手に置き換えず、候補を確認するか名前を言い直します。 認識の補正にはLunaを利用できるが、モデルの確信度だけでは本人確定としない。

名前が出た人物と目の前の相手は同一とは限らない。会話で調べたい対象を扱い、顔や声から本人を識別しない。

| 範囲 | 内容 |
| --- | --- |
| 必須 | G2音声・短文表示、スマホの手入力補正、会社/人物候補の照合、Web調査、根拠確認、停止・縮退・費用記録 |
| 最初の情報源 | 会社公式サイト、本人の公開プロフィール、登壇者紹介等 |
| SNS | X/Facebookはアクセス可能性を確認した連携だけ追加。利用できなくても公式サイトで成立させる |
| 話題 | 事業・公開活動・登壇、本人が公表した趣味、事実として確認できる共同活動 |
| 今回の対象外 | 同意・明示開始のない録音、原音の永続保存、背景での録音継続、顔認識、非公開情報、ログイン制限回避、交友関係の推測、センシティブ属性推定、自動投稿/DM、CRMへの自動登録 |
| 人の判断 | 音声処理の開始/停止、曖昧な対象の確認、話題を実際の会話に使うか |

趣味・交友情報は必須出力にしない。写真やフォローから「親友」等を推測せず、共同登壇なら共同登壇と書く。見つからない情報を埋めず、事業等の確認できる話題を返す。

## カード例（架空デモ資料）

```text
対象：架空企業A / デモ人物A
公開活動：製品設計の勉強会に登壇
話題案：設計で一番難しかった点は？
出典：主催者紹介 [1] / 取得時刻
```

最大4組をスマホでは2×2、G2ではSDK標準の文字で同時表示する。事実は28字以内・質問は26字以内の完結した短文を優先し、省略記号で切らない。安全に短縮できない場合は元の全文を使う。16px画像描画は明示選択する試験用で、その場合だけ枠に合わせて全文を縮小する。根拠本文・URL・公表日/取得時刻と全文はスマホの選択した出典詳細で確認する。確認できた0〜4件だけを採用し、不足する枠は「未確認」として架空の補完をしない。会話中のG2シングルタップは対象をリセットして「聞き直す」、ダブルタップとシステム終了は音声停止とする。G2の日本語の見切れと読みやすさは実機での確認が必要。

目標案：評価セット中の別人混同0件、出典欠落0件。対象確定から最初のカードまで中央値10秒以内、調査全体20秒で打切り。音声認識と確認待ちは別計測。いずれも未計測で、一般利用の無誤り保証ではない。

## ログインと再利用QR

単回・最大10分のQRに加え、指定期限まで繰り返しログインできる再利用QRを扱う。再利用QRは最大48時間・有効なもの5枚までで、期限は延長しない。どちらの発行も認証と利用コードの再確認を必須とし、QR利用者はコードなしで交換できる。再利用QRは発行元のログアウトやサーバー再起動では失効せず、フラグメントを再訪用に保持する。生トークンをサーバーに永続保存しない。

会話は新規の空セッションから始め、認証は無操作15分で失効する。明示開始した会話中の更新を含め開始から最大12時間、またはQR等の短い期限までとする。会話データの保持窓は別の最大15分とし、録音・有料調査を自動開始しない。端末の認証記憶は最大12時間とQR期限の早い方まで。QR取消は以後の交換を拒否するが、交換済み端末の記憶を一括取消する意味ではない。「終了して削除」はその端末の会話と認証記憶を失効させる。WebViewでの保持・再読取は実機未検証。[操作とAPI](../RUNNING.md#ログイン用qrの使い分け)。
