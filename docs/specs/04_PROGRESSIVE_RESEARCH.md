# 段階的な調査・表示

2026-09-22の追加要求「最近の投稿などすぐ取得できる情報を素早く表示したい。遅く取得されるのは表示も段階分けして遅く」に対応するConstructionの変更記録。既存の要件確認・レビュー・マージの委任を引き継ぎ、公式AI-DLCの段階承認を遡って記録しない。

## 要件と動作

- PRG-01: 最近のX投稿・公開プロフィールを先に取得し、本人性と本文を検証した4件以内の速報を表示する。過去投稿検索とSNS取得を待たない。最初の調査の制限は20秒。
- PRG-02: 速報後に全期間のX検索、Facebook、Instagramを並行取得し、各情報源が届くたびに検証して表示を更新する。実行全体は開始から90秒以内、LLM最大6回、検索/API処理最大5回、ページ取得最大9回。公開する根拠は6件、表示カードは4件以内。
- PRG-03: 速報・Xの追加時は最近X 2件、過去X 1件、人物会社1件を優先。SNSを確認できた段階では有用なSNS 1件、最近X 2件、過去X 1件を優先し、不足は他の確認済み資料で補う。SNSの投稿日を表示し、古い投稿を「最近」と断定しない。
- PRG-04: 音声認識と次の人物抽出は調査と並行する。同じ人物・通常の発話では調査を継続し、新人物では前の調査を中止する。要求ID・対象版・表示世代を照合し、遅い旧結果は破棄する。
- PRG-05: 追加の取得・通信・検証が失敗しても速報の根拠付きカードは維持する。本人の曖昧さが見つかった場合は、他APIの停止処理を待たず表示を消して確認に戻す。終了・リセット・期限切れでも処理と表示を停止する。

## データ・費用・復旧

ApifyはMeta公式APIとは別の公開データ取得サービス。本人サイト等で紐付けを確認した個別アカウントだけを候補とし、取得した著者名、URL、投稿日、本文を検査する。さらに実際に取得したX/Webの本人資料を必要とする。家族・健康など既存の話題制限を維持し、SNSプロフィールのヘッダーを投稿本文の事実に混ぜない。

APIキーはサーバーの非公開設定のみ。Instagram/Facebook各回で最大3投稿、Actor費用上限$0.10・60秒・自動再実行なし。開始リクエストの応答不明時は再送しない。判明済みの外部実行IDは中止時に停止要求を送る。停止を確認できない場合も外部の期限・上限が残る。

公開投稿のキャッシュはSNS別に最大5分（失敗・空結果は30秒）、最大32件。会話本文は共有キャッシュに入れない。呼出前の費用予約・匿名集計は維持する。応答時の料金は参考値であり、確定請求として予約を解放しない。

## 受入条件と証拠

| 対象 | 確認すること | 自動試験 |
| --- | --- | --- |
| PRG-01 | 過去検索/Web待機中でも速報が届く | `progressive-x`, `progressive-agent` |
| PRG-02/03 | 情報源別の到着で4件以内を更新、投稿本文だけを採用 | `progressive-agent`, `social-provider`, `main` |
| PRG-04 | 同人物・通常会話は継続、新人物の後に旧結果を表示しない | `main`, `http` |
| PRG-05 | 追加障害では速報保持、本人不明と中止では即消去 | `progressive-agent`, `main`, `http` |
| 費用・安全 | 投稿者/ホスト拒否、上限、キャッシュ、中止、秘密非公開 | `social-provider`, `progressive-agent` |
