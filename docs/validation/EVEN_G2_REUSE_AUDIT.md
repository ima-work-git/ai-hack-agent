## 最小限の移植対象

- 接続adapterのホスト検出、bridge接続、startup page、3段テキスト配置、入力イベント、音声開始・停止の骨格。
- `header`・`content`・`footer`を持つ表示用データ構造。人物・カードの識別情報は今回の共有契約に合わせて追加する。
- スマホの3段表示プレビューとHTMLエスケープの処理。画面にはプレビューと実機の状態を別々に示す。
- WebSocketの送受信境界、QR起動・パッケージ生成の手順。認証・検証・接続先設定を追加して使う。

既存の業務状態、解析ロジック、デモデータ、業務別カード、既存単体テストは移植対象外です。REQ-001・005の接続基盤に利用し、REQ-002〜004の抽出・人物照合・調査・根拠評価は新規実装します。REQ-006〜009の復旧・上限・データ保護・計測も別途実装と検証が必要です。

## SDK 0.0.12の型定義で確認した契約

| API / データ | 型・値 | 移植時の扱い |
| --- | --- | --- |
| `createStartUpPageContainer` | `Promise<StartUpPageCreateResult>`。0=成功、1=invalid、2=oversize、3=outOfMemory | 0以外を成功扱いしない |
| `textContainerUpgrade` | `Promise<boolean>` | false・例外・応答待ちを検知し、表示成功と区別 |
| `audioControl` | `Promise<boolean>`。`AudioInputSource.Glasses` は `glasses` | 成功応答と受信状態を確認し、失敗時は録音中表示を確定しない |
| `audioEvent.audioPcm` | `Uint8Array`。音声イベントには入力元 `source` もある | 入力元・録音状態・要求の有効性を検査 |
| `onDeviceStatusChanged` | `DeviceStatus`を受け取り、解除関数を返す | `connectType`の切断・失敗を扱う |
| `onEvenHubEvent` | イベント購読の解除関数を返す | 背景移行・終了・再接続時の購読を管理 |
| `OsEventTypeList` | `FOREGROUND_ENTER_EVENT`・`FOREGROUND_EXIT_EVENT`が存在 | 復帰と明示的な録音開始を分離 |

これらはインストール済みSDKの宣言を確認した結果で、端末側の実動作確認ではありません。音声形式・表示制約は連携ガイドに従い、実機で再確認します。

## コードから見つかった修正候補

以下は静的なコード確認に基づく候補で、実機上の障害を再現した結果ではありません。

| 候補 | 今回の修正・確認点 |
| --- | --- |
| PCMイベントを録音状態に関係なく送信口へ渡す | 同意・capturing状態・30秒上限・入力元・有効セッションで受信と送信を制限し、停止後のフレームを拒否 |
| 音声開始の戻り値を待たず録音表示を変える。通信接続前のPCMを落とす可能性 | 通信準備とマイク開始結果を確認。欠損時は再入力へ戻し、無制限に音声を蓄積しない |
| 表示を短時間で集約するが、前回の更新完了前に次の更新を開始できる | 更新を直列化し、各戻り値を確認。送信直前にも要求ID・対象の版・失効を検査 |
| 接続状態・背景移行イベントを使わず、終了処理で内部状態の解除が不十分 | 購読・タイマー・保留表示・接続状態を解除。復帰は有効runの確認と利用者操作を経て行い、自動録音しない |
| 受信JSONは型キャストのみ。通信認証・再接続・待ち時間制限が未実装 | Schema検証、認証、Origin検査、上限付き再接続、古い応答の棄却を追加 |
| 接続先許可は手順例にあり、既存アプリ設定には未追加 | 今回の接続先を許可リストに設定し、サーバーのCORS・認証と合わせて検証 |
| 終了しても既存の文字起こし・カード等の状態が残る | 今回の明示終了・失効時の削除要件に置換。個人データと非識別の費用集計を分ける |
| ホストとUser-Agentから実機／模擬を分類する | SDK送信受付、端末の接続状態、実際に見えた結果を区別して記録 |
