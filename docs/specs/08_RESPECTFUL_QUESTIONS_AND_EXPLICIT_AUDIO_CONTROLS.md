# 自然な推奨質問・音声操作の明示確認・同意済み運用

2026-09-23のユーザー追加要求。追跡：[Issue #30](https://github.com/ima-work-git/ai-hack-agent/issues/30)。

> 同日追補：[仕様09](09_QR_CONVERSATION_START.md)により、専用の会話用QRの読み取りを開始操作として扱い、認証・G2・ASR準備後に一度だけ会話を開始する。本文の「QRだけでは開始しない」とC-01の当該部分はこの追補で置き換える。通常ページ・履歴復帰・停止後からの自動開始禁止、音声操作の分離、事前同意の運用は維持する。旧検証結果は当時の条件の記録として残す。

本仕様は、[仕様01](01_INTENT_AND_REQUIREMENTS.md)の毎回の同意確認UI、[仕様06](06_CONTINUOUS_AUDIO_AND_PERSON_CONTROLS.md)・[仕様07](07_SEARCH_CHOICES_AND_NAVIGATION.md)の確認なし単一タップによる聞き直し／音声再開を置き換える。それ以外の本人性、本文根拠、費用集計、停止と保持期限は維持する。以前の検証結果を今回の実機受入結果として扱わない。

## ユーザー要求

- 推奨質問を、浅い定型や失礼な問いではなく、相手の活動に関心を示す自然な質問にする。
- 出典への移動を承認したタップが、音声のリセットや再開として処理されないようにする。
- 事前に同意を得て利用する運用とし、毎回の同意チェックボックスをなくす。録音の開始は引き続き利用者が明示する。

## 推奨質問

LLMは選択した根拠の活動・製品・出来事について、会話で相手に直接尋ねられる質問を1件ずつ作る。相手の選択、経験、関心など、事実の繰り返しでは得られない具体点を丁寧に聞く。4件で同じ定型を繰り返さない。

詰問、採点、侮蔑、根拠のない称賛を避ける。成功・失敗・苦労・感情などを根拠なしに前提としない。すでに示した氏名・所属・日付を単純に聞き返したり、話題の内容を一律に「投稿のきっかけ」へ置き換えたりしない。過去の投稿には当時の文脈を保つ。

架空の例：

| 取得した事実 | 関心を示す質問例 | 避ける例 |
| --- | --- | --- |
| 試作アプリを公開した | 試作アプリで、特に試してほしい機能はありますか？ | 本当に自分で作ったんですか？ |
| モデルを比較した記事を公開した | モデル比較で、印象が変わった点はありましたか？ | 投稿のきっかけは？ |
| 昨年、開発勉強会で登壇した | 当時の開発勉強会で、特に伝えたかったことは何ですか？ | 登壇はいつですか？ |

例文を固定テンプレートとして全員へ使わない。短いグラス用質問も同じ具体点と丁寧さを保ち、安全に短くできない場合は全文を使う。質問の検査では「なぜ」「工夫」「失敗」の単語だけを理由に自然な質問まで一律排除しない。検査は本人性や事実の検証を代替せず、短い文を整えるために事実を生成しない。

## G2操作

SDKの単一タップ・ダブルタップ・上下スクロールを使う。3回タップや長押しが独立した操作として通知されるとは仮定しない。adapterはタップを音声リセットへ直接結び付けず、画面の現在の確認状態で意味を決める。

| 状態と操作 | 動作 |
| --- | --- |
| 確認なしで1回タップ | 音声開始・再開・対象リセットを行わない |
| 4件一覧で下スクロール | 本文を維持して、出典への移動確認を出す |
| 一覧またはカードなしで上スクロール | 音声継続中は「聞き直す」、音声エラー停止時は「音声を再開」の明示確認を出す |
| 出典内で上下スクロール | 前後の出典または一覧への移動を確認する。音声エラー画面に変わった後の上スクロールは再開確認 |
| 確認中に1回タップ | 表示している操作だけを1回実行する |
| 確認中に2回タップ | 確認を取り消し、音声状態を変えずに留まる |
| 確認なしで2回タップ | 根拠付きカードの人物を固定し、ASRとその人物の追加調査を続ける |
| カードなしで下スクロール | 提示済みの検索候補があれば選択確認を出す |

同じ確認に回答したタップを通常操作へ再配信しない。SDKの重複通知、単一タップとダブルタップの組合せを考慮し、一つの物理操作から移動と音声リセットが連続発生しないようにする。時間差のある正当な次の操作まで継続的に抑止しない。

出典移動・取消は録音、ASR接続、人物抽出、対象、費用予約をリセットしない。明示した「聞き直す」の承認時だけ対象と古い調査・保留音声を破棄し、既存の音声接続で新しい発話を待つ。「音声を再開」の承認時は有効な認証・可視状態などの条件を再確認する。スマホの明示的な聞き直し／再開ボタンも維持する。

停止、画面非表示、切断、ログアウト、認証期限切れ、対象変更で不要になった確認を破棄する。古い確認や遅着イベントから音声を起動しない。出典の追加取得・並べ替えでも、表示中の出典ID・引用文・ページ位置との対応を保ち、置換済みの出典へ誤移動しない。

## 同意済みの利用条件

ユーザーの明示指示により、会話相手への説明・同意は利用前に済ませる運用を採用する。アプリは毎回の同意チェックボックスを要求しない。これは運用上の前提であり、アプリやCodexが第三者の同意を確認・取得したという証拠ではない。録音による同意証跡や「同意取得済み」の監査記録を作らない。

QR読取、ログイン、G2接続、ページ表示だけでは録音・有料調査を開始しない。「会話モードを開始」などの明示操作は必要。停止・終了・画面非表示・切断・ログアウト後は、進行中の音声／抽出／調査を中止し、遅い応答を破棄する。復帰だけで自動再開しない。会話相手の意向が変わった場合は利用者が停止・終了する。

マイク許可、入力元の明示、認証、送信先、原音非保存、最大15分の会話保持、外部APIの利用条件、費用計測は従来どおり。UIの省略を、未知の第三者に対する同意取得の代替とは扱わない。

## 受入条件と大会要件

- **Q-01**：根拠に対応した自然な質問を生成し、既知事実の聞き返し・詰問・根拠のない前提を検査する。短縮後の質問も同じ趣旨を保つ。
- **G-01**：確認なし単一タップ、および出典移動／取消では音声API・対象リセットを呼ばない。
- **G-02**：聞き直し／再開は表示した確認への明示承認時だけ実行し、重複イベントで二重実行しない。
- **G-03**：停止・背景・ログアウト後の古い確認や非同期応答では処理を再開しない。追加情報で出典の対応を壊さない。
- **C-01**：チェックボックスなしで明示開始できる。QR読取や復帰だけでは開始せず、停止手段を維持する。同意の証拠を捏造しない。
