## 検証結果

- 型検査・資料リンク検査・本番ビルドを実行。
- Vitestの自動試験：228件成功、行カバレッジ95.24%（集計対象は設定どおり。画面エントリーポイントとサーバー起動ファイルを除外）。ネットワーク/SDK/音声は模擬、HTTPはメモリ内のリクエスト/応答ストリーム、画面回帰はhappy-domを使用。
- 実ブラウザー（ローカルサーバー、架空資料）：通常調査で自律的な追加検索→2カード、同姓同名で人の選択待ち→別会社の候補選択→対象どおりの1カード、検索障害で検証済み1カードへの縮退、画面更新・出典表示を確認。リロード後は「再開」を要求し、自動で旧カードを表示しないことを確認。
- 開発サーバーへの `/.private/.session-key`、絶対パスの`/@fs/…/.private/.session-key`、`/server/config.ts` はHTTP 403。レスポンス本文に秘密を表示せず、ステータスだけ確認。
- EvenHubパッケージ生成：静的UIの梱包に成功。バックエンド接続・実機動作の証明ではない。
- 上記は初回MVP時点の結果。2026-09-22の追加作業でOrcaRouter・Tavily・Xの実API接続と費用上限の設定を確認した。実STT、Even G2、費用明細の照合は未実施。最終方式では出典付き2カードを返した。[実API検証記録](LIVE_API_VALIDATION.md)に結果と制約を記載する。

## 独立レビューで修正したこと

1. 中止後に画面とサーバーの対象版がずれ再開できない問題：連番を強制せず、単調増加とUUID重複拒否を使用。
2. 録音停止の待機中に中止しても旧音声を送る競合：音声の世代、同意、可視性を送信前に再検査。pagehideで先に無効化。
3. 再開の遅着による旧カード復活・DEMO/LIVE表示の混同：認証と表示世代を確認し、モードを復元。
4. 開発時の静的配信から保存鍵へアクセスできる構成：Viteで秘密保存先とサーバー側のソースを明示拒否し、実HTTPで403を確認。
5. 梱包CLIが出力失敗でも0で終了する問題：出力先作成と生成ファイルの存在・サイズ確認を追加。
