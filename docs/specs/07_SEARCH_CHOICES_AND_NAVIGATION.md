- 公開検索の実際のキーワードと別候補を表示し、正しい候補を選べるようにする。

## 採用する振る舞い

1. G2のスクロールでは本文を維持し、下部に移動確認を表示する。確認中の1回タップは移動、2回タップは取消。確認がない通常状態の1回は人物聞き直し、2回は人物固定という前仕様を維持する。音声エラー・終了・対象変更で古い確認を破棄する。
2. 4件は事実と「推奨質問」を改行し、各番号の間にも空行を置く。長い根拠文は既存のページ表示を維持する。質問の具体性を保ち、表示短縮で一律の定型質問へ上書きしない。
3. Webの送信検索語、Xの照会ハンドル／投稿取得ハンドル／全期間検索式、Instagram・Facebookの取得プロフィールURLを実呼出直前に通知する。キャッシュを新規API呼出と表示せず、初回・追加・過去・SNSの段階を区別する。全文会話やAPIキーを検索履歴へ混ぜない。
4. 現在の発話に基づく人物候補・所属あり／なし・公式プロフィール／公開活動などの候補を最大4件表示する。根拠のない著名人を埋め草にしない。スマホの候補ボタンで選択し、カードがまだないG2ではスクロールで候補を示し1回タップで選択・2回で取消する。
5. 選択先はサーバーが同じ会話へ提示した候補IDから解決する。クライアント任意の対象・検索語を選択APIでは受理しない。古い調査・音声入力をリセットし、新しい一度限りの調査要求を発行する。ASRと既存会話予算は継続し、人物本人性・本文根拠の確認は省略しない。
6. 検索候補も会話データの保持期限で削除する。同意撤回・非表示・終了後に遅い応答から調査を再開しない。
